# Movimientos

## Objective
Implement the Movimientos screen from `docs/redesign/movimientos.png` with real backend and web behavior.

## Scope and decisions
- Server-side filtering, search, stable pagination, selected details, monthly KPIs, responsive navigation and screen.
- Register, correct through reversal/replacement, duplicate, split categories, and reverse movements without deleting financial history.
- Present a transfer as one logical movement; create/reverse both ledger legs atomically.
- Investment contributions/disposals affect an owned cash account and link to an investment. Valuations remain cash-neutral. Preserve immutable cash history; do not infer realized profit or silently rewrite cost basis.
- Exclude transfers/investment cash movements from income/expense/budget totals; retain their balance effects. Never sum mixed native currencies; show per-currency totals without an explicit supported conversion.
- Default to active movements with an explicit audit/history view.
- User explicitly chose ACTIVE-ONLY category reports/budget spending: exclude reversed originals and reversal rows; corrections count only replacements. Replace existing gross-spending budget behavior with tested active semantics.
- Category allocations are immutable child rows of one ledger transaction, inherit currency, use positive exact decimals and sum exactly to parent amount. Never duplicate balance effects. Ordinary correction must persist reversal+replacement+allocations atomically.
- Receipt upload/storage is explicitly deferred by the user. No fake receipts or nonfunctional upload controls.
- Preserve unrelated work and `docs/redesign/`. Current branch: `feat/mobile-web-parity`.
- No background servers, database seeding/manual changes, external resource provisioning, or edits to old migrations. New migrations only via EF tooling; do not apply to the developer database.
- No commits, push, PR, or merge without explicit user authorization. Work-unit commit evidence remains pending authorization.
