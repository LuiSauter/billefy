# Android-first web parity

## Objective
Replace the Kotlin Multiplatform mobile prototype with real web-equivalent workflows, delivered Android-first with reusable shared logic. The user explicitly selected Android first; iOS host and platform integrations are deferred.

## Problem and approach
Mobile currently uses local authentication flags, example financial data, and close-only handlers. Build a secure authenticated vertical slice before extending modules; do not label visual prototypes as functional.

## Scope and constraints
- Feature branch: `feat/mobile-web-parity`, based on the current web feature branch.
- Preserve all pre-existing dirty backend/web/docs changes; source edits are restricted to `mobile/`.
- Android first; no iOS host in this delivery sequence.
- Server remains the calculation/persistence authority; decimal money, immutable ledger, FX snapshots, user-confirmed ingestion only.
- Secure token storage, explicit OAuth configuration, no secret/PII logging.
- Document every new environment variable in `mobile/.env.example` and `mobile/README.md`.
- No background servers, database data insertion, or schema manipulation.
- RDD currently off (global); use native ASSESS and proportionate functional verification.
- No commits without explicit user request. Work-unit commit identities remain pending rather than invented; no push/PR/merge authorized.
- Review workload: full parity is a multi-module feature, not one reviewable patch; route bounded single-writer units and reassess each unit.
